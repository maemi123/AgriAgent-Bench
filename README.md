# AgriAgent-Bench（农业工程课程作业）

**面向种植决策的大模型智能体长程规划与纠偏能力评测基准**

> 浙北杭嘉湖平原 · 单季晚稻 · 一个完整生长季 ≈ 160 步决策

农业大模型已经能回答「这株稻子缺不缺氮」，但还没有一把尺子能衡量它**能不能把一季地种好**。本项目把一整个生长季压缩成一个可复现的仿真环境：智能体每天看一次天气预报和田间状态，选一个动作，共同跑完 160 天，最后按效益 / 产量 / 合规 / 过程四个维度打分。

## 1. 总结

在 279 次完整生长季运行中，五条程序化基线拉出 **35.7 — 95.1** 的得分区间；DeepSeek V4.1-Flash 实测 9 局均分 **73.8**，落在"只收不管"与"农技规则"之间——**它的效益分反超人写规则 3.6 分，却在合规与农时节奏上掉了 7 分。**

## 2. 为什么需要这个基准

| 现有基准 | 评什么 | 缺什么 |
|---|---|---|
| AgriBench (CVPPA@ECCV 2024) | 景观图像识别与描述 | 最高只到"给建议"，不闭环 |
| AI-AgriBench (2026) | 416 道专家审核农学题 | 前沿模型准确率 >95%，**已饱和** |
| SwissCrop25 (2026) | 遥感作物制图精度 | 评感知，不评管理决策 |

共同特征：**输入静态、答案唯一、评分靠比对**。而真实农业决策正好相反——输入随天气变化，答案不唯一，好坏要看一个季度之后。

## 3. 环境机制（三分钟版）

### 3.1 田里只有 6 个数字

| 状态 | 含义 | 初值 |
|---|---|---|
| `swc` | 土壤含水量 (mm) | 58 |
| `n_soil` | 土壤速效氮 (kg/亩) | 3.2 |
| `biomass` | 相对生物量 0–1 | 0.05 |
| `pest` | 病虫压力 0–1 | 0.02 |
| `weed` | 杂草压力 0–1 | 0 |
| `gdd` | 有效积温 (℃·日) | 0 |

生育期按**有效积温**推进（生物学零度 10℃），而不是按日历：分蘖 300 → 拔节 1100 → 抽穗 1900 → 灌浆 2350 → 成熟 2790。这样冷年与暖年才可比，评测才是公平的。

### 3.2 每天一次出手机会，六个动作

| 动作 | 效果 | 成本 | 违规条件 |
|---|---|---|---|
| 灌溉 | 水位 +0~30 mm | 6 元 + 0.15 元/mm | 晒田期（GDD 900–1150）灌溉 |
| 施肥 | 氮 + 用量 × 0.55 | 5.6 元/kg | 单次 >12 kg；成熟期追氮 |
| 施药 | 病虫 ×0.18、杂草 ×0.30 | 25 元 | 成熟期施药 |
| 巡田 | 获得精确状态（带误差） | 8 元 | — |
| 等待 | 无 | 0 | — |
| 收获 | 季末结算 | 120 元 | 未熟抢收 |

**关键时序**：动作发生在当天天气结算**之前**。它决定今天灌不灌水，依据的是预报；明天才知道对不对。整个基准的张力就在这条时间缝里。

### 3.3 一天怎么走

```
积温推进 → 水分平衡（降雨 − 蒸散 − 渗漏）→ 氮素吸收与淋洗
        → S 形生长 → 病虫草增殖 → 生育期判定
```

病虫只在 **日均温 >24.5℃ 且 湿度 >80%** 的日子增长，是天气的函数，不是随机数。

### 3.4 产量与评分

```
产量 = 640 × 生物量 × 病虫损失 × 杂草损失
病虫损失 = 1 − 0.30 × 穗期（GDD 1900–2650）病虫峰值
```

只算**穗期峰值**而非全季平均：抽穗灌浆期被咬直接是空壳，分蘖期掉几片叶子还能长回来。这是"提前预防"值钱的机制来源。

| 维度 | 权重 | 口径 |
|---|---|---|
| 效益 | 45 | 净收益 / 480 |
| 产量 | 20 | 亩产 / 600 |
| 合规 | 15 | 每次违规扣 4 |
| 过程 | 20 | 分蘖肥、晒田、孕穗保水、病虫控制、适时收获，各 4 分 |

只看钱，最优解是"啥也不干"；只看产量，最优解是拼命打药。四维互相牵制，正是为了逼出"会种地"而不是"会刷分"。

## 4. 结果

### 4.1 五条基线（2024–2026，ECMWF 7 天预报，135 次运行）

| 策略 | 产量 (kg/亩) | 净收益 (元/亩) | 总成本 | 病虫峰值 | 总分 |
|---|---|---|---|---|---|
| 全知上界 | 551.7 | +507.3 | 982 | 0.17 | **95.1** |
| 规则 + 预报 | 488.4 | +375.0 | 944 | 0.13 | **80.1** |
| 农技规则 | 493.6 | +355.1 | 978 | 0.13 | **78.8** |
| 只收不管 | 294.0 | +203.7 | 590 | 0.55 | **50.8** |
| 随机乱动 | 579.3 | −1001.0 | 2565 | 0.09 | **35.7** |

三个可复用的观察：

1. **排序在 9 个站点年上无一例外**，说明状态转移与评分方向自洽。
2. **随机策略产量最高（579）却分数最低**——成本是规则的 2.6 倍。只看产量会把专家骗过去，按净收益立刻现原形。
3. **"规则"与"规则+预报"只差一处**（灌溉前看不看 7 天雨），差值 +1.3 分即预报信息的边际价值。

### 4.2 预报时效消融（9 个站点年）

| 时效 | 相对无预报增益 | 降水相关系数 r |
|---|---|---|
| 3 天 | +1.0 | — |
| **5 天** | **+1.5**（拐点） | 0.57 |
| 7 天 | +1.3 | 0.365 |

**看得更远 ≠ 看得更准**：7 天预报的降水相关系数只剩 0.37，一半是噪声，错误的预报会诱导错误决策。

### 4.3 换预报源（2021–2023，JMA 7 天预报，135 次运行）

JMA 7 天的 r 仅 0.21 / 0.07，同样一套规则，预报增益掉到 **−0.3 / +0.4**（EC 是 +1.3）。

> 结论：**信息的价值取决于预报技巧，而不是数据量。**

### 4.4 大模型实测（DeepSeek V4.1-Flash，9 局）

| 维度 | 大模型 | 农技规则 | 差 |
|---|---|---|---|
| 效益 (45) | 36.9 | 33.3 | **+3.6** |
| 产量 (20) | 13.9 | 15.4 | −1.5 |
| 合规 (15) | 10.1 | 15.0 | **−4.9** |
| 过程 (20) | 12.9 | 15.1 | −2.2 |
| **总分** | **73.8** (σ=4.2) | 78.8 | −5.0 |

一句话：**不是不会算账，是不守规矩、抓不住农时。** 9 局里 7 局的病虫峰值越过 0.35 安全线，波动区间 0.157–0.450。

> 样本量只有 9 局、单一模型，只用来验证"评测台能跑通"，不用于下模型强弱结论。

## 5. 快速开始

无需安装依赖（Python 3.9+ 标准库即可）：

```bash
git clone https://github.com/maemi123/AgriAgent-Bench.git
cd AgriAgent-Bench/agriagent-bench

# 跑一局农技规则基线（湖州南浔 2024，7 天预报）
python -c "
from agents import build_agent
from run_pilot import run_episode
sc, _ = run_episode(build_agent('rule'),
                    'data/weather_huzhou_nanxun_2024.json', 0,
                    'data/forecast_huzhou_nanxun_2024.json', 7)
print(sc['score_total'])
"

# 五条基线全量（3 站点 × 3 年 × 3 种子）
python run_pilot.py --forecast-days 7

# 换一个真实大模型跑（OpenAI 兼容接口）
export AGRIBENCH_BASE_URL="https://your-endpoint/v1"
export AGRIBENCH_API_KEY="sk-..."
export AGRIBENCH_MODEL="your-model-id"
python run_llm.py --workers 1
```

`run_llm.py` 逐局追加写入 `results/llm_results_<model>.jsonl`，支持断点续跑，不会重复计费。

## 7. 数据来源与边界

| 数据 | 来源 | 覆盖 | 说明 |
|---|---|---|---|
| 历史天气 | ERA5（Open-Meteo 转发，0.25°） | 2016–2026 | 3 站点：湖州南浔 / 嘉兴桐乡 / 杭州余杭 |
| 历史预报（主实验） | ECMWF IFS，Previous Runs API | **2024-03 起** | 7 天时效，逐日起报 |
| 历史预报（扩展） | JMA GSM，Previous Runs API | **2021 起 lead1–7** | 变量较少（降水、气温、湿度） |

**为什么主实验只有 2024–2026？** ECMWF 的历史预报存档从 2024 年 3 月才开始；更早的年份中，只有 JMA 保留了 7 天时效的逐日起报，因此 2021–2023 单独作为扩展验证表报告，不与主表混算。

**为什么不用 GFS 补 2024 前的空缺？** 实测 Open-Meteo 上 GFS / ICON / UKMO / GEM / CMA / BOM 在 2024 年前均无 7 天时效的逐日存档，唯一可用的是 JMA。

## 8. 已知简化（答辩时主动说明）

- 单田块、单作物、**无空间异质性**；不区分具体病原，只建模病虫压力指数。
- **每天只能提交一个动作**。现实中施肥与打药可以同一天做，这里压缩为单选是为了让机会成本显性化；但"巡田"（买信息）混在动作里占用当日配额，是已知缺陷，后续会拆成"作业组合 + 信息动作"两层。
- 产量模型为经验式，目标是**决策逻辑的可比性**，不追求与实测产量逐点吻合。
- LLM 实测样本为 9 局单模型，仅验证流程闭环。
